Timesheets IA — Three Problems, Three Solutions
Synthesized from the June 30 Timesheet AI check-in  ·  Renata, Victor, Cody, Victório
Core finding
This isn't a navigation bug. It's a broken mental model — and every navigation fix built on top of it will keep feeling wrong.
Three overlapping issues compound each other: the names don't reflect reality, two zoom levels are implemented as separate pages, and the member selector means different things in different places. Each can be fixed independently — the rename alone has the highest leverage.

Problem 1 — Taxonomy rot

The words "Timesheet" and "Time Log" have been stretched beyond their original meaning. The approval workflow hijacked the word Timesheets, and the view/edit page got the leftover name Time Log. Neither name tells you what you'll find.

"Why isn't it just called Approvals? If that's what it was built for, it's the approval process. All of the time you want to see is already on the other page."

— Cody Rogers, June 30

Because the zoom is a page change, it causes:

✗
A back button on a top-level menu item
Users arrive via a top-level nav click — not by drilling down — so the back button reads as a bug, not a feature.
✗
Header filters jump when switching views
Multi-member and single-member share a header, but the filter set changes on switch — causing a visible layout jump that reads as broken.
✗
Member click opened a new browser tab (until recently)
Two tabs for what felt like the same page — a symptom of treating the zoom as a separate route.

Problem 3 — Filter behavior inconsistency

The member selector looks identical in both pages but does fundamentally different things. Victor named it precisely: "Selecting and unselecting isn't the same as filtering — it's going back and forth in granularity of data."

Why this matters for the fix Any solution that tries to unify the header between the two views will run into this. The member selector has different semantics in each context — unifying the header without resolving this just moves the confusion around.

Solution options

A — Rename + one-page zoom
Do now

Rename Time Log → Timesheets and Timesheets → Approvals to fix the taxonomy. Default to multi-member view. Selecting one member changes the content beneath a static header — no new page, no new tab. Keep the back link as a conservative safety net.

Pros

  • Low dev effort
  • Highest leverage — fixes naming for everyone: users, CSMs, devs
  • No new patterns to learn
  • Matches the agreed mental model (multi-member as default)

Cons

  • Member selector still has dual semantics
  • Header filter inconsistency not fully resolved
  • Back button/deselect logic still awkward at the edges
B — Side drawer  ·  Solves all three problems
Follow-up project

Multi-member is always the base state. Clicking a member opens a side drawer with their detail view. No navigation — header never changes, filters stay put, zoom in/out is just open/close.

C — Explicit breadcrumb / zoom indicator
Consider

Frame the zoom levels as a hierarchy with a breadcrumb: All Members → Helen. "All Members" is always clickable and acts as "clear selection." More explicit than deselecting, less confusing than a back button.

Pros

  • Familiar pattern (file explorer, breadcrumb nav)
  • Makes zoom level explicit
  • Minimal component changes

Cons

  • Doesn't resolve filter semantics
  • Logic gets messy when teams + members both selected
  • Doesn't fix header jump

Recommended path

01

Now — Option A (Rename + one-page zoom)

Ship the rename and navigation fix in the current project. Time Log → Timesheets, Timesheets → Approvals. Default to multi-member. Single-member is a content swap, not a page nav. Keep the back link as a safety net — known pattern, low risk.

02

Next — Prototype the side drawer

Validate whether the daily/weekly timeline view actually works inside a drawer. Zone has the component. If it fits, the drawer becomes the follow-up project that permanently resolves filter semantics and the header jump.

03

After shipping — confirm the rename landed

The rename has the highest leverage of any change here — it corrects the mental model for users, CSMs, engineers, and future designers. After shipping, check support volume to see if "Timesheets vs. Approvals" confusion drops.
